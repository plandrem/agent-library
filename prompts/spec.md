# Create a technical specification for a new feature

Create a new .md file under ./specs: draft the plan we would need to implement the following feature:

$ARGUMENTS

Break the plan into these sections:

- High Level Objective
- Final Project Directory + File Structure
- Type Changes
- Method Changes
- Test Changes
- Self Validation (this should include the instructions to run the validation, plus the comprehensive set of input/output pairs that you would need to see to be convinced that the feature is working and all edge cases are handled)
- Task List (a detailed todo section, indicating validation steps for each todo that confirm the step was truly completed successfully. The audience consists of over-eager, inexperienced engineers who need a lot of hand-holding and supervision. Err on the side of granularity for the steps, and select validation and tests that are more likely to fail. Consider the project as a graph, implement each of the leaves with comprehensive testing before moving to higher nodes in the graph. Begin each implementation section with a written list of all assumptions about the input data structures for that node. For test cases, use a bulleted list explaining what each test does rather than code.)

Code changes should be described in English or MINIMAL pseudocode, not real code. 

Write out the plan. Ultrathink.
